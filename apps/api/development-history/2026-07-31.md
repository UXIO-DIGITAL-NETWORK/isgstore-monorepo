**Repository:** `integration/web-topup-api`
**Stack:** Laravel 13 · PHP 8.3+ · PostgreSQL · Monetapay · Digiflazz · Discord Webhooks
**Role in platform:** Headless REST API — the single backend consumed by both frontend SPAs

## Key Decisions Made

**1. Promo code applied server-side in the Action layer**
Client sends a promo code at checkout; the `ApplyPromoAction` validates expiry, usage limits, and minimum order value before calculating the discount. The gateway is only charged the post-discount amount. This prevents any client-side discount bypass.

**2. Order form schema is data-driven, not hardcoded**
`order_form_fields` on the Category model stores the field schema (`{fields: [...], customer_no_template: "..."}`) as JSON. Checkout validation reads from this schema, so adding a new game with custom fields (e.g., a server selector) requires no code change — only a data update.

**3. Storefront routes separated from admin routes at the routing layer**
`routes/api.php` now has distinct route groups for public storefront, authenticated member storefront, and admin. Rate limiting, middleware stacks, and authorization policies are applied per group. This prevents accidental admin endpoint exposure to storefront consumers.

**4. Single topup page response (no round-trips)**
The topup page endpoint bundles game metadata, product SKUs (grouped by tier), and payment methods into one response. The SPA gets everything it needs to render the page in a single call.

**5. Supervisor direct-start fallback**
On a fresh server where `supervisorctl` has never started the daemon, `supervisorctl reload` fails. The deploy script now checks if `supervisord` is running and falls back to a direct start, making first-deploy idempotent.

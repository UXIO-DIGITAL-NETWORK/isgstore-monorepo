- `layouts/CategoryTabsLayout.tsx` — tab `value`, `label` and `segment`
- `features/dashboard/components/DashboardNavbar.tsx` — `CATEGORY_TAB_LABELS` key **and** value. `getCategoryBreadcrumb` derives `Add ${tabLabel}` from it, so `Category › Category Server › Add Category Server` follows with no second edit

### Category Server tab (product_requirements.md §4.5 lines 229-235, §6 line 271)

- **Data layer:** new `CategoryServer` entity (`id`, `name`, `options: {name, value}[]`, timestamps) — **the only entity in this feature with no `status` field**, which the contract test asserts explicitly. 3 deterministic fixtures (one with no options, to cover the empty case), a mock-backed service, query hooks, and a Zod schema.
- **List:** header "Category Server" + real subcopy, toolbar with search and "+ Add Category Server" (no parent filter), and exactly three columns — `No. / Category Server Name / Action`. No Status column, no checkbox column.
- **Row menu:** two items, `Edit Category Server` and `Delete`. **No deactivate/activate** — this entity has no status concept, unlike Category Type. The list test asserts the menu contains exactly those two, since a copy-paste from the sibling tab would silently add a third.
- **Add / Edit:** one page-based form, `useParams({strict:false})` + RHF `values` re-sync, same as the other tabs.
- **Preview mirror:** `index`, `add` and `$categoryServerId/edit` all mirrored under `/admin/categories-preview/category-server/*`.

### New pattern: the Name/Value option builder

`components/CategoryServerOptionsBuilder.tsx` — a `useFieldArray` list of `{name, value}` pairs behind a "+ Add Option" button. Same mechanism as `CategoryFormFieldsBuilder`, deliberately simpler: two plain text inputs per row, no type or required metadata. Per-row `<Label htmlFor>` with index-unique ids so each input has its own accessible name.

**Inferred addition:** the reference shows a single row with no way to remove it. A repeatable list you can only grow is a dead end, so each row gets a ghost `Trash2` button labelled `Remove option N`, copying the sibling builder's affordance. Flagged as not-pictured.

- Main field labelled **"Category Type Name"** → `Category Server Name`. That's a leftover from copy-pasting the Add Category Type form built immediately before this one, not a second reference to category types. The add-form test asserts the old label is *absent*, not just that the new one is present.
- Footer "of 9999999 **transactions**" → "of N **category servers**" via the existing `entityLabel` prop.

The shared `DeleteConfirmDialog` built on 2026-07-27 was **reused, not rebuilt**; this tab passes its own two strings and nothing else. That consolidation paying off is the whole point of having done it.

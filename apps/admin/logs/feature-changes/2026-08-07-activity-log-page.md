# 2026-08-07 — Activity Log page

**Scope:** activity (new feature slice) + sidebar nav + admin route
**Type:** feat
**Author/agent:** you

## What changed
- New `src/features/activity/` slice browsing the admin-wide audit feed from
  `GET /v1/activity-logs`: `types`, `services/activity.service.ts` (maps the snake_case
  `ActivityLogResource` → camelCase view row, `id` via `toRowId`), `hooks/useActivityLogs.ts`,
  `components/activityColumns.tsx` (Actor · Type badge · Message · IP · Time), and
  `pages/ActivityLogPage.tsx` (header + message search + paginated `DataTable`).
- Registered route `src/routes/admin/_protected/activity/index.tsx`
  (`requirePermission("activity.view")`).
- Enabled the sidebar item: `DashboardSidebar.tsx` "Activity" now links to `/admin/activity`
  (was `disabled`).
- Extended the `fakeApi` `/v1/activity-logs` fixture with `type`, `ip_address`, `user_id` and
  null-role/ip for `System` rows so the new columns render real content in tests.

## Why
- The endpoint already existed and is deployed on `main`/staging; only the admin UI was missing.
  Reused the existing `products`/`transactions` list pattern and shared `DataTable` /
  `unwrapPaginated` / `toRowId` / `formatRelativeTime` rather than new infrastructure.
- Read-only page (no action column): activity rows are written by the backend across the app,
  never from the admin.

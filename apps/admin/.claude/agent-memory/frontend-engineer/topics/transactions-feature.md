# `transactions` feature

Built 2026-07-10 (UI+routing; data layer was already built same day). Polish pass same day (pill grid, rounding, real pagination, scrollbar, modal transition).

## TransactionsTable
`src/features/transactions/components/TransactionsTable.tsx` — **feature-local, server-mode** sibling to dashboard's `DataTable`: `useReactTable({ ..., manualPagination: true })`, data prop is already the current page's slice from `PaginatedResponse<T>` (no client pagination). Same loading/empty/error shape as `DataTable` plus a footer: page-size `Select` + literal `` `${from}-${to} of ${total} transactions` `` text + the shadcn `pagination.tsx` primitive (`Pagination`/`PaginationContent`/`PaginationItem`/`PaginationLink`/`PaginationPrevious`/`PaginationNext`) rendering a small `page ± 2` window of numbered links (clamped to `[1, lastPage]`, no ellipsis needed at this scale) — **revised from a plain Previous/Page-N-of-M/Next button pair on the polish pass** once the reference showed numbered pages; reuse the `pageWindow()` helper pattern for any other server-paginated table. `PaginationLink`/`Previous`/`Next` use `href="#"` + `onClick` with `event.preventDefault()` (not real routes) since these are query-param page changes, not navigation. Generic over `TData` even though only `Transaction` uses it today.

Uses `Table`'s `containerClassName` prop (see `topics/shared-components.md`) for a real, always-visible horizontal scrollbar styled with token-based arbitrary-variant utilities — reinstates the "slider below the table rows" the original build had correctly omitted (it was unlabeled/decorative in the reference); now it's functional native `overflow-x-auto`, just visually styled.

## Fixture volume for real pagination
`src/features/transactions/data/transactions.data.ts` has 10 hand-authored exact/near-exact rows plus `generateSyntheticRows(30)` appended (~40 total) so `lastPage = 4` at the default page size — without this, pagination UI would always show 1 page. `meta.total` in the service response stays a deliberate `9999999` placeholder (unrelated to real row count); only `last_page` is derived from real fixture length.

## RowActionMenu
`transactions/components/RowActionMenu.tsx` — shadcn `DropdownMenu`, one consistent 7-item menu for every row (no success/failed variant — Figma access was denied to confirm one exists, both times this feature was touched). Takes a `showCallbackActions` boolean prop (default `true`) to hide the 2 provider-callback items (Resend Callback/Retry Invoice) for Manual's reduced action set, rather than forking the component. Wraps "Edit Invoice"/"Delete" in `<Can permission="transactions.edit">`/`<Can permission="transactions.delete">` — first real consumer of `<Can>` inside a dropdown menu (works fine as a plain conditional-render wrapper around `DropdownMenuItem`).

## Native drag-and-drop dropzone pattern
`EditTransactionDialog.tsx` — no new dependency: a `Box` with `onDragOver`/`onDragLeave`/`onDrop` (all `event.preventDefault()` on drag-over/drop) wrapping a visually-hidden real `<input type="file" accept="...">` (raw `<input>` is an allowed exception per `custom-components.md`) plus a "Browse files" `Button` that calls `fileInputRef.current?.click()`. Both the drop handler and the input's `onChange` funnel into one `handleFiles(files: FileList | null)` that does `setValue("proofFile", file, { shouldValidate: true })` (RHF). Reuse this exact shape for any future file-upload field.

## Edit dialog rounding + transition (polish pass)
`EditTransactionDialog`'s `<DialogContent>` takes an instance-level `className` override (`rounded-2xl duration-300 data-[state=open]:zoom-in-90 data-[state=closed]:zoom-out-90`) for a more pronounced pop transition than the shared `ui/dialog.tsx` default (`rounded-lg`/`duration-200`/`zoom-*-95`) — scoped to this one dialog via `cn()` merge (tailwind-merge resolves the conflicting radius/duration/zoom utility groups), not a change to the shared primitive. Internal fields (`Select` triggers, `Input`, the dropzone `Box`, footer `Button`s) all got `rounded-xl` the same way. **Same scoping approach applies anywhere "make this rounder" means one screen, not the whole app** — override via instance `className`, never edit `components/ui/*` for a single-consumer ask.

## TransactionFilterBar
`transactions/components/TransactionFilterBar.tsx` — one component shared by both tabs via a `fields?: FilterField[]` prop (default = all 10 Automatic fields; Manual passes a reduced array) rather than forking the bar. Internal (unexported, to dodge `react-refresh/only-export-components`) `FilterSelect`/`FilterDate` sub-renderers DRY up the 5 near-identical `Select` fields and 2 `Popover`+`Calendar` date fields. Every field's `<Label htmlFor>` points at the `SelectTrigger`/`Button`'s matching `id` — `getByLabelText` finds Radix Select/Popover triggers this way same as a native input. Exports the `TransactionFilters` type (`Pick<TransactionListParams, ...>` minus `page`/`per_page`) and `FilterField` union — consumed by both pages. Individual `Input`/`SelectTrigger`/date-picker `Button` all carry `rounded-xl` (polish pass, scoped via `className`, not the shared `ui/input.tsx`/`ui/select.tsx`).

## StatusBadge / StatusPills
`StatusBadge` maps `TransactionStatus` -> label + `text-success`/`text-destructive`/`text-muted-foreground` (monochrome, only 2 statuses get real color).

`StatusPills` — **revised on the polish pass** from 3 compact `Tooltip`-wrapped `Button`s (accessible name `"{label} ({count})"`) into a full-width `grid grid-cols-1 md:grid-cols-3` of stat-card-style buttons: label top-left, big `tabular-nums` count on the right, each with a status-colored 2px border (`border-warning` for Pending, `border-chart-1` for Partial Refund, `border-destructive` for Partial Success) and a stronger tint (`ring-*/40 bg-*/10`) when active/toggled. Label and count are now **separate text nodes** — tests must assert both are present within the button (`within(button).getByText("12")`) rather than matching one exact accessible name string like `"Pending (12)"`.

**New `--warning` token** (`src/index.css`, amber OKLCH values mirroring the `--success` authoring pattern) was added specifically for the Pending pill — the 3rd functional-color exception alongside success/destructive (documented in `design_system.md §3`). User-approved addition, not an invented one; ask before adding a 4th.

## Test gotcha — label text collisions across sections on the same page
The filter bar's "Invoice Status"/"Search" labels collide with the Edit dialog's "Invoice Status" label and the sidebar's "Search" trigger respectively. Scope with `within(screen.getByRole("region", { name: "Transaction Filters" }))` (the filter bar has this landmark) or `within(screen.getByRole("dialog", { name: "..." }))` — same "never scope by className, use a real landmark" rule as the Monthly Performance card precedent.

## Lint gotcha
Non-component exports (e.g. a `const ALL_FIELDS: FilterField[] = [...]`) living in the same file as an exported component trip `react-refresh/only-export-components` in feature code (unlike `components/ui/**`, which is exempted). Same trap bit a shared hook: `Can.tsx` originally exported both `useCan` and `<Can>` from one file — split `useCan` into `src/hooks/useCan.ts` (global hooks live in `src/hooks/` per `system_architecture.md §3`) to fix it. If a helper array/function is only used internally, don't export it at all rather than hitting the lint error; if a hook and a component both need exporting, put them in separate files.

## Fixed-input `user-event.upload()` gotcha
`@testing-library/user-event`'s `upload()` silently no-ops on a visually-hidden (`className="hidden"`, i.e. `display:none`) native `<input type="file">` — it never fires the underlying `change` event. Use `fireEvent.change(fileInput, { target: { files: [file] } })` instead for any hidden file input (same category of gotcha as the clipboard stub in `topics/testing-patterns.md`).

# `transactions` feature

Built 2026-07-10 (UI+routing; data layer was already built same day). Two polish passes same day: #1 (pill grid, rounding, real pagination, scrollbar, modal transition), #2 (permanent pill tint + hover, radius consistency across all cards, table sort/select/drag-reorder, warning-colored Processing badge, colorized Profit/Admin-fee/timestamp sub-text).

## TransactionsTable
`src/features/transactions/components/TransactionsTable.tsx` — **feature-local, server-mode** sibling to dashboard's `DataTable`: `useReactTable({ ..., manualPagination: true })`, data prop is already the current page's slice from `PaginatedResponse<T>` (no client pagination). Same loading/empty/error shape as `DataTable` plus a footer: page-size `Select` + literal `` `${from}-${to} of ${total} transactions` `` text + the shadcn `pagination.tsx` primitive (`Pagination`/`PaginationContent`/`PaginationItem`/`PaginationLink`/`PaginationPrevious`/`PaginationNext`) rendering a small `page ± 2` window of numbered links (clamped to `[1, lastPage]`, no ellipsis needed at this scale) — **revised from a plain Previous/Page-N-of-M/Next button pair on the polish pass** once the reference showed numbered pages; reuse the `pageWindow()` helper pattern for any other server-paginated table. `PaginationLink`/`Previous`/`Next` use `href="#"` + `onClick` with `event.preventDefault()` (not real routes) since these are query-param page changes, not navigation. Generic over `TData` even though only `Transaction` uses it today.

Uses `Table`'s `containerClassName` prop (see `topics/shared-components.md`) for a real, always-visible horizontal scrollbar styled with token-based arbitrary-variant utilities — reinstates the "slider below the table rows" the original build had correctly omitted (it was unlabeled/decorative in the reference); now it's functional native `overflow-x-auto`, just visually styled.

## Fixture volume for real pagination
`src/features/transactions/data/transactions.data.ts` has 10 hand-authored exact/near-exact rows plus `generateSyntheticRows(30)` appended (~40 total) so `lastPage = 4` at the default page size — without this, pagination UI would always show 1 page. `meta.total` in the service response stays a deliberate `9999999` placeholder (unrelated to real row count); only `last_page` is derived from real fixture length.

## RowActionMenu
`transactions/components/RowActionMenu.tsx` — shadcn `DropdownMenu`, one consistent 7-item menu for every row (no success/failed variant — Figma access was denied to confirm one exists, both times this feature was touched). Takes a `showCallbackActions` boolean prop (default `true`) to hide the 2 provider-callback items (Resend Callback/Retry Invoice) for Manual's reduced action set, rather than forking the component. Wraps "Edit Invoice"/"Delete" in `<Can permission="transactions.edit">`/`<Can permission="transactions.delete">` — first real consumer of `<Can>` inside a dropdown menu (works fine as a plain conditional-render wrapper around `DropdownMenuItem`).

## Native drag-and-drop dropzone pattern
`EditTransactionDialog.tsx` — no new dependency: a `Box` with `onDragOver`/`onDragLeave`/`onDrop` (all `event.preventDefault()` on drag-over/drop) wrapping a visually-hidden real `<input type="file" accept="...">` (raw `<input>` is an allowed exception per `custom-components.md`) plus a "Browse files" `Button` that calls `fileInputRef.current?.click()`. Both the drop handler and the input's `onChange` funnel into one `handleFiles(files: FileList | null)` that does `setValue("proofFile", file, { shouldValidate: true })` (RHF). Reuse this exact shape for any future file-upload field.

## Edit dialog rounding + transition (polish pass)
`EditTransactionDialog`'s `<DialogContent>` takes an instance-level `className` override (`rounded-2xl duration-300 data-[state=open]:zoom-in-90 data-[state=closed]:zoom-out-90`) for a more pronounced pop transition than the shared `ui/dialog.tsx` default (`rounded-lg`/`duration-200`/`zoom-*-95`) — scoped to this one dialog via `cn()` merge (tailwind-merge resolves the conflicting radius/duration/zoom utility groups), not a change to the shared primitive. Internal fields (`Select` triggers, `Input`, the dropzone `Box`, footer `Button`s) all got `rounded-xl` the same way. **Same scoping approach applies anywhere "make this rounder" means one screen, not the whole app** — override via instance `className`, never edit `components/ui/*` for a single-consumer ask.

## TransactionFilterBar
`transactions/components/TransactionFilterBar.tsx` — one component shared by both tabs via a `fields?: FilterField[]` prop (default = all 10 Automatic fields; Manual passes a reduced array) rather than forking the bar. Internal (unexported, to dodge `react-refresh/only-export-components`) `FilterSelect`/`FilterDate` sub-renderers DRY up the 5 near-identical `Select` fields and 2 `Popover`+`Calendar` date fields. Every field's `<Label htmlFor>` points at the `SelectTrigger`/`Button`'s matching `id` — `getByLabelText` finds Radix Select/Popover triggers this way same as a native input. Exports the `TransactionFilters` type (`Pick<TransactionListParams, ...>` minus `page`/`per_page`) and `FilterField` union — consumed by both pages. Individual `Input`/`SelectTrigger`/date-picker `Button` all carry `rounded-xl` (polish pass, scoped via `className`, not the shared `ui/input.tsx`/`ui/select.tsx`).

## StatusBadge / StatusPills
`StatusBadge` maps `TransactionStatus` -> a color pair, not just text: `STATUS_BADGE_CLASS` sets **both** `text-*` and `border-*` to the same token per status (`success`/`destructive`/`warning`/neutral `border-border`) — not the shadcn `outline` Badge variant's default neutral `border-border` override, which only colored the text and left every badge's border gray. `processing` uses `text-warning border-warning` (2nd polish pass — the reference showed it amber, not neutral). Extend `STATUS_BADGE_CLASS`, not a one-off className override, when a new status needs a color.

`StatusPills` — full-width `grid grid-cols-1 md:grid-cols-3` of stat-card-style buttons: label top-left, big `tabular-nums` count on the right, each with a status-colored 2px border (`border-warning` for Pending, `border-chart-1` for Partial Refund, `border-destructive` for Partial Success). **2nd polish pass**: the tinted background (`bg-*/10`) is now **permanent**, not only-when-active — active/toggled state layers a stronger `ring-2 ring-*/30 bg-*/20` on top; `hover:bg-*/15` + `transition-colors duration-200` added for the hover-in-between state. Label and count are separate text nodes (not one `"{label} ({count})"` string) — tests must assert both are present within the button (`within(button).getByText("12")`), not one exact accessible name.

**New `--warning` token** (`src/index.css`, amber OKLCH values mirroring the `--success` authoring pattern) was added specifically for the Pending pill and the Processing badge — the 3rd functional-color exception alongside success/destructive (documented in `design_system.md §3`). User-approved addition (asked via a clarifying question, not invented); ask before adding a 4th.

All Automatic/Manual page-level card containers (header, filter bar, table wrapper) and the status pills now share one radius (`rounded-2xl`) so the whole screen reads as one consistent card system, matching the table card's radius the user pointed at as the reference. ## Table sort / row-select / drag-reorder (2nd polish pass)
`TransactionsTable` gained three features in one pass, all real user decisions (not invented) — see `.claude/plans/` history for the Q&A: **real service-backed sorting** (not visual-only), **all columns sortable** except Action, **selection-UI-only** (no bulk-action bar), **client-only drag reorder via `@dnd-kit`** (resets on refetch, not persisted — reordering a transaction list has no real backend meaning).

- **Sorting**: lifted to the page (`sorting`/`onSortingChange` props, `SortingState` from `@tanstack/react-table`), included in query params as `sortBy`/`sortDir`, real-sorted in `transactions.service.ts` via a `SORTERS: Record<string, (t: Transaction) => string | number>` map keyed by column id (extend this map, not the table, when a new sortable column needs a custom accessor).
- **Gotcha — `header.column.getCanSort()` requires an `accessorFn`**: TanStack's built-in capability check is `(enableSorting ?? true) && !!column.accessorFn`, so `id`-only columns (no `accessorKey`) — which is most of this table's columns (User/Product/Cost/Status/Method/Time) — always report `getCanSort() === false` regardless of `enableSorting`, even under `manualSorting: true` where the accessor is never actually used to compute anything. Since sorting here is fully manual/service-backed, check `header.column.columnDef.enableSorting !== false` directly instead of `getCanSort()` — bypasses the accessor requirement entirely. Only exclude "action" (and the synthetic `__select`) via an explicit `enableSorting: false` on those column defs.
- **Row selection**: a synthetic `__select` `ColumnDef` (checkbox header/cell) prepended to the real columns, `enableRowSelection: true` + `state.rowSelection` local to `TransactionsTable` (not lifted — no bulk actions this pass). **Gotcha — memoize synthetic inline columns**: defining `selectColumn` fresh in the component body (a new object/functions every render) makes `flexRender` see a new `cell`/`header` function identity each render and remount that column's cells — which silently drops in-progress state like "just-checked" right after the click that set it (caught by a test asserting `toBeChecked()` immediately after `user.click`; passed visually in a manual browser check because a full re-render still lands on the correct end state, just wastefully). Fix: wrap the synthetic column def in `useMemo(() => ({...}), [])` and `fullColumns` in `useMemo(() => [selectColumn, ...columns], [selectColumn, columns])`. Same principle applies to any inline `ColumnDef` defined inside a component body, not just this one.
- **Drag reorder**: `orderedData` local state (`useState(data)`, reset via `useEffect` on `[data]` so a refetch/filter/sort/page change always wins over any in-progress manual order), `DndContext` (`PointerSensor` + `KeyboardSensor` w/ `sortableKeyboardCoordinates` for a11y) wraps the `Table`, `SortableContext` wraps the body rows (`items` = row ids, `verticalListSortingStrategy`). **One `useSortable({id})` call per row** (in a `SortableRow` wrapper, not duplicated in a separate drag-handle component) — `setNodeRef`+`transform`/`transition` go on the `TableRow`, `setActivatorNodeRef`+`attributes`+`listeners` go on the handle `Button` inside it, so only the handle starts the drag. The drag-handle column itself is **hand-rendered inside `SortableRow`**, not a TanStack `ColumnDef` — calling `useSortable` twice for the same id (once for the row, once for a column-based handle) double-registers it incorrectly. `getRowId: (row) => row.id` on `useReactTable` (constrains `TransactionsTable<TData extends { id: string }>`) keeps selection/sort/drag-order state keyed consistently across reorders. dnd-kit announces moves via an ARIA live region automatically (no extra work needed) — confirmed via a real keyboard drag (Space → Arrow → Space) in a manual browser check.
- **`Button`/`TableRow` now `forwardRef`** (`src/components/ui/button.tsx`, `src/components/ui/table.tsx`) — needed for `setActivatorNodeRef`/`setNodeRef`. Backward-compatible (existing callers that don't pass `ref` are unaffected) — same additive pattern as `Table`'s `containerClassName` prop.

## Colorized sub-text (2nd polish pass)
In `automaticColumns.tsx`: Cost column's "Profit: X" and Method column's "Admin fee: X" are two nested `Text` elements — the label stays `variant="muted"`, only the value span gets `text-success`/`text-warning` — **fixed colors regardless of the row's outcome** (the reference showed the same green/amber on both a success and a failed example row, so this isn't conditional per-row logic, just a semantic color identity for "profit" vs. "fee"). The Time column's resolved-timestamp line (`{outcomeLabel}: {date}`) **is** conditional — `text-success` when `invoice_status === "success"`-ish, `text-destructive` when `"failed"` — since that line's label itself already alternates Success:/Failed: per row.

## Test gotcha — label text collisions across sections on the same page
The filter bar's "Invoice Status"/"Search" labels collide with the Edit dialog's "Invoice Status" label and the sidebar's "Search" trigger respectively. Scope with `within(screen.getByRole("region", { name: "Transaction Filters" }))` (the filter bar has this landmark) or `within(screen.getByRole("dialog", { name: "..." }))` — same "never scope by className, use a real landmark" rule as the Monthly Performance card precedent.

## Lint gotcha
Non-component exports (e.g. a `const ALL_FIELDS: FilterField[] = [...]`) living in the same file as an exported component trip `react-refresh/only-export-components` in feature code (unlike `components/ui/**`, which is exempted). Same trap bit a shared hook: `Can.tsx` originally exported both `useCan` and `<Can>` from one file — split `useCan` into `src/hooks/useCan.ts` (global hooks live in `src/hooks/` per `system_architecture.md §3`) to fix it. If a helper array/function is only used internally, don't export it at all rather than hitting the lint error; if a hook and a component both need exporting, put them in separate files.

## Fixed-input `user-event.upload()` gotcha
`@testing-library/user-event`'s `upload()` silently no-ops on a visually-hidden (`className="hidden"`, i.e. `display:none`) native `<input type="file">` — it never fires the underlying `change` event. Use `fireEvent.change(fileInput, { target: { files: [file] } })` instead for any hidden file input (same category of gotcha as the clipboard stub in `topics/testing-patterns.md`).

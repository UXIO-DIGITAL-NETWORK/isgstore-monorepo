# API Integrator — Project Memory

> **STATUS:** backend is **separate and not built yet**. Deliver a typed data layer where the mock->real swap is one file per service. `auth`, `dashboard`, `financial`, `transactions` (2026-07-10, data-layer-only, no UI/routes yet), `integration` (2026-07-10, promoted from roadmap same day per `product_requirements.md §4.4`), and `categories` (2026-07-11, promoted from roadmap same day per `product_requirements.md §4.5`, data + UI + 5-tab routing all in one pass) have real data layers today.

## Contracts
- `src/types/api.type.ts`: `ApiResponse<T> = { status: "success"|"error"; code: number; message; data: T }` (`code` confirmed against the real login response 2026-07-13), `ApiError = { status; message; errors }` — **but** the real staging 422 (failed login) body observed is `{ message, errors }` with **no `status` field**, so `ApiError` is still provisional. **`PaginatedResponse<T>`** (shipped 2026-07-10) = Laravel paginator `{ data: T[]; links: {first,last,prev,next}; meta: {current_page,from,last_page,path,per_page,to,total} }`.
- Global entities: `src/types/models/` (migrate `src/models/user.model.ts` here). Provisional (pending API): `Transaction`, `BalanceMovement`, `Game`, `Product`, view-models `DashboardSummary`/`FinanceSummary` (`product_requirements.md §6`).

## Patterns (reference the shipped auth feature — **real staging HTTP since 2026-07-13**)
- Service returns the **payload directly** (interceptor unwraps `response.data`): `features/auth/services/auth.service.ts` -> `api.post("/auth/login", data)` typed `Promise<AuthApiResponse>`, param `LoginPayload = LoginFormValues & { timezone: string }`. Timezone is auto-detected (`src/utils/getBrowserTimezone.ts`) and merged in the hook's `mutationFn` — never a form field, `loginSchema` stays `{email,password,remember}`.
- Mutation hook: `features/auth/hooks/useLogin.ts` -> `useMutation({ mutationFn: (values) => authService.login({...values, timezone: getBrowserTimezone()}), onSuccess: (res, vars) => { setAuth(res.data, vars.remember); navigate({to:"/dashboard"}); } })`. Login `data` is `{ user, access_token, refresh_token }` (confirmed envelope).
- Query hook (new): `useQuery({ queryKey:[...], queryFn: () => service.list(params) })`; server-side tables send `page`/`per_page`/`sort`/`filter[...]`/`search`, type against `PaginatedResponse<T>`.

## Mock-swap seam (this phase)
- Each feature service exposes a typed interface (e.g. `transactionsService.list(params): Promise<PaginatedResponse<Transaction>>`), implemented against **typed fixtures in `features/<f>/data/`** (optionally a small artificial delay). Later, replace only the service body with real `api.*` calls. Optionally gate via `ENV.USE_MOCKS`. **Never put mock data in components.**

## Testing (TDD, mandatory — set up on first use)
Same Vitest + RTL harness as frontend (`src/test/setup.ts` + `test-utils.tsx`), shared across the whole app — don't build a second one. Before implementing a service or hook, write a failing test asserting its typed contract/shape (mock fixture matches the type; list params like `page`/`sort`/`filter[...]` map correctly), confirm it fails for the right reason, then implement to green. Colocated `*.test.tsx` next to the service/hook file.

## Wiring facts
- `api` in `src/lib/axios.ts` (STAYS): Bearer from `useAuthStore`, unwraps `response.data`, on 401 (not `/auth/login`) `clearAuth()` + redirect `/login`. Base URL `ENV.API_BASE_URL` (`src/config/env.ts`); `.env` targets staging `https://api-staging-topup.uxio-dev.web.id/api/v1` (base includes `/v1`). Real failed login is **422**, not 401. Interceptor is testable without network via a per-request `adapter` that rejects a hand-built `AxiosError` (see `src/lib/axios.test.ts`) — `window.location` is unstubbable in jsdom, assert on store state instead.
- `QueryClient` is inline in `src/main.tsx`; `src/lib/react-query.ts` is empty -> move the client + defaults there.
- `useAuthStore` (`src/store/useAuthStore.ts`): `token`/`refreshToken`/`user` persisted in `access_token`/`refresh_token`/`auth_user` cookies via `js-cookie` (`setAuth(data, remember)` writes all three; expiry 30d vs session; `setToken` was removed as dead code). `permissions` derived from `user.role_id` via a **stopgap map** (`1 -> ["*"]`, else `[]` — pending a backend permissions scheme); token-only sessions with no user cookie default to `["*"]`. `refresh_token` is stored but **no refresh-on-401 flow exists yet**. `User` (`src/models/user.model.ts`) is the confirmed real shape incl. `role_id`/`phone`/`balance`/`point`/`locale`/`timezone` — type-only accuracy, build no admin UI on `balance`/`point`/`locale`.
- Uploads: multipart `FormData` helper (no S3). Polling: `refetchInterval`, stop on terminal status. Never call the payment/provider gateway directly.

## Decisions log
- Two envelopes: `ApiResponse<T>` (single/action) + `PaginatedResponse<T>` (lists). Provisional entity fields until the real contract lands — revise then, and log it.
- **Dashboard data layer shipped (mock-backed, no UI yet)** — `src/features/dashboard/{types,data,services,hooks,tests}/`. Read-only, all `useQuery` (no mutations): `useStatCards`, `useChartSeries(month: MonthOption)`, `usePendingOrders`, `useActivityLog`, `usePerformanceRows(tab: PerformanceTabKey)` in `hooks/useDashboard.ts` (`useOperator`/`getOperator`/the `Operator` fixture were deleted 2026-07-13 — operator identity now comes from `useAuthStore.user`, set by the real login), backed by `dashboardService` (`services/dashboard.service.ts`) and typed fixtures in `data/*.data.ts`. `dashboardService.getChartSeries` **throws** on an unknown month (not `undefined`) — precedent for future "unknown key" service methods unless a spec says otherwise.
- **Shared formatting utils promoted to `src/utils/`** (not feature-scoped, since multiple features need them): `src/utils/currency.ts` (`formatCurrency`, `Intl.NumberFormat("id-ID", ...)` normalized to replace its non-breaking-space output with a regular space for deterministic string equality) and `src/utils/date.ts` (`formatRelativeTime` — coarse m/h/d "Ago" labels via `date-fns` diff fns + `vi.useFakeTimers()`/`setSystemTime` in tests, not a `baseDate` param; `formatBannerDate` via `date-fns format`). Both reusable by `financial`/`transactions` next.
- **Fixtures never bake relative/derived display strings** — e.g. `ActivityLog.timestamp` is a raw ISO string; the UI computes "5m Ago" at render via `formatRelativeTime`. Keep fixtures as raw data, format at the edge.
- **Financial data layer shipped** (mock-backed, no UI logic) — `src/features/financial/{types,data,services,hooks,tests}/`. Read-only `useQuery` hooks in `hooks/useFinancial.ts`: `useSummaryCards`, `usePaymentGateways`, `useSuppliers`, backed by `financialService` (`services/financial.service.ts`) and fixtures in `data/*.data.ts`. `summary-cards.data.ts` reuses `StatCardData` imported from `@/components/common/StatCard` (not a feature type — that type now lives with the promoted `StatCard` component). `PaymentGatewayBalance`/`SupplierBalance` are genuinely feature-local (`features/financial/types/financial.type.ts`) per product_requirements.md §6 — don't promote to `src/types/models/` unless another feature needs them too.
- Hook tests use `renderHook` from `@testing-library/react` (v16, no separate `@testing-library/react-hooks` needed) with a local `QueryClientProvider` wrapper (`retry: false`) — one representative hook is enough smoke coverage since the `useQuery` pattern repeats identically across a service's hooks; no need to test every hook exhaustively.
- **Transactions data layer shipped (mock-backed, data-layer-only — no pages/routes yet, frontend layer builds those next)** — `src/features/transactions/{types,data,services,schemas,hooks,tests}/`. Entity + params in `types/transaction.type.ts` (`Transaction`, `TransactionListParams` = the PRD §4.3 10 filter fields + `page`/`per_page`, `StatusCounts`, a feature-local `SelectOption` — no shared one exists yet, promote if a second feature needs it). Fixtures in `data/transactions.data.ts` (10 rows) + `data/select-options.data.ts` (filter-bar select lists). `services/transactions.service.ts`: `list`/`getById`/`getStatusCounts`/`edit`/`refund`/`resendCallback`/`retryInvoice`/`remove`. `hooks/useTransactions.ts` mirrors `useLogin.ts`'s mutation shape but for non-navigating mutations: `onSuccess -> invalidateQueries({queryKey:["transactions"]}) + toast.success`, `onError -> toast.error`. `schemas/editTransaction.schema.ts` is the first Zod file with a `z.instanceof(File)` upload validation (type + ≤10MB size via `.refine`, whole field `.optional()`) — reuse this pattern for any future upload form.
  - **Paginated mock list pattern:** `list(params)` filters the fixture array in-memory, slices by `page`/`per_page` (default 1/10), but sets `meta.total` to a **literal placeholder** (e.g. `9999999`) instead of the real filtered/fixture length whenever the reference UI shows a placeholder count that doesn't match the mock dataset size — a deliberate exact-fidelity call, not a bug. `meta.from`/`meta.to` still reflect the real slice.
  - **Mock mutations still validate:** rather than a no-op `Promise.resolve()`, mock mutations that take an `id` look it up in the fixture array and `throw` if missing (mirrors `getById`) — keeps ESLint happy (no unused params) *and* gives the mutation a real failure path for free; a `reason`-style param gets a trivial non-empty check for the same reason.
  - **FormData mutation body:** `edit(id, formData)` reads fields via `formData.get("key")`, merges onto the found fixture row (cast the string back to the field's union/type), bumps `updated_at` — no in-memory mutation of the shared fixture array itself (keeps the fixture module pure/re-testable).
- **Integration data layer shipped** (data + UI together, single-pass build) — `src/features/integration/{types,data,services,hooks,tests}/`. `IntegrationChannel` (`types/integration.type.ts`) is feature-local **snake_case** (`connection_status`, `logo_url`, `last_ping_at`) — deliberately not merged with financial's camelCase `PaymentGatewayBalance`/`SupplierBalance` even though channel names overlap (e.g. "UxioPay" appears in both fixture sets): money vs. connectivity are different concerns per `product_requirements.md §4.4/§6`, don't share the type just because the real-world referent overlaps. Single `useChannels()` hook (`hooks/useIntegration.ts`) backed by `integrationService.getChannels()` and 7 fixtures in `data/channels.data.ts`.
  - **First `refetchInterval` polling hook in the repo** (`system_architecture.md §4.9` had zero prior usage) — `useChannels` polls every 30s with **no stop condition**, unlike transaction-status polling: connectivity is never a terminal state, a channel always needs re-pinging. Precedent for any future "never terminal" polling hook.
  - Fixtures are **inferred, not confirmed**: omitted financial's 5th supplier (`UxioTopup` — plausibly in-house, needs no external channel) and added a 2nd payment gateway (`Monetapay`, a cross-project assumption) beyond financial's sole `UxioPay`. Revisit both once real channel data exists.
- **Categories data layer shipped** (data + UI together, single-pass build, same day as the roadmap promotion). `Category` (`types/category.type.ts`) is feature-local **snake_case** per `product_requirements.md §6`: `id, type, uid_parser, name, sub_name?, account_nickname_validation?, region?, code, slug, status: "active"|"inactive", order_form_fields: {key; label?; required?}[], created_at, updated_at` — `order_form_fields` is the buyer-facing dynamic field-definition array with a direct-but-not-yet-wired relationship to the consumer storefront's order form (nothing calls the consumer app; captured in the shape only). `services/categories.service.ts` is full CRUD (`list`/`getById`/`create`/`update`/`remove`) against an **in-memory mutable copy** of the fixture array (`const categories = [...CATEGORIES]`) rather than the read-only fixture constant itself — needed so `create`/`update`/`remove` are visible across calls within a test/session; this is the first feature service to mutate its own working copy rather than treating fixtures as fully immutable. `hooks/useCategories.ts` mirrors the transactions mutation shape (`onSuccess -> invalidateQueries(["categories"]) + toast.success`, `onError -> toast.error`), plus a component-level `onSuccess` on `useCreateCategory().mutate(input, {onSuccess: navigate})` for the Add-form's post-save redirect — hook-level and call-site `onSuccess` both fire, that's expected React Query behavior, not a bug.
  - `categoryFormSchema` (`schemas/categoryForm.schema.ts`, Zod v4) enforces the reference's real product guidance as an actual validation rule, not just display copy: a `.refine` blocks `key === "whatsapp" | "email"` (case-insensitive) on every `order_form_fields` row with the message "Reserved key — buyer contact is taken from their account." — reuse this "encode the info-callout text as a real Zod refine" move whenever a reference's guidance text implies an actual constraint.

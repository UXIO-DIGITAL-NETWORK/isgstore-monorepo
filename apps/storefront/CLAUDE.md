## Commands

```bash
npm run dev       # Start Vite dev server
npm run build     # TypeScript check + Vite production build
npm run lint      # ESLint
npm run preview   # Preview the production build locally
```

There are no test scripts configured. Environment variable `VITE_API_BASE_URL` sets the backend URL (default: `http://localhost:8000/api`).

## Architecture Overview

Feature-based architecture with strict isolation. The routing layer is a thin registry; all business logic lives inside `src/features/`.

### Routing (TanStack Router — file-based)

- `src/routes/` files are **registry-only** — they must not contain any JSX. They only import a `component` from `src/features/` and optionally call a middleware in `beforeLoad`.
- `src/routeTree.gen.ts` is auto-generated by the TanStack Router Vite plugin — **never edit it manually**.
- The `_auth` route group uses `beforeLoad: () => requireGuest()`. Add protected routes analogously with `requireAuth()`.

### Middlewares

`src/middlewares/authMiddleware.ts` exports `requireAuth()` and `requireGuest()`. All route guard logic goes here, never inline in route files.

### State Management

| Concern | Tool |
|---|---|
| Server / API data | TanStack Query (`useQuery`, `useMutation`) |
| Global client state | Zustand (`src/store/`) |
| Local component state | React `useState` |

Never use Zustand to cache API responses. Never use `useEffect` for data fetching.

### Features (`src/features/[name]/`)

Each feature is self-contained with its own `components/`, `pages/`, `hooks/`, `services/`, `schemas/`, and `types/`. Features **must not import from each other**. Share only via `src/types/` (global entities like `ApiResponse<T>`).

Internal feature structure:
- `pages/` — "smart" components; wire hooks to UI
- `components/` — presentational ("dumb") components
- `services/` — raw API call functions using `api` from `src/lib/axios`
- `hooks/` — `useMutation`/`useQuery` wrappers
- `schemas/` — Zod schemas for runtime validation
- `types/` — TypeScript interfaces for API responses and feature-local types

Export feature public API through the feature's `index.ts`.

### HTTP Client (`src/lib/axios.ts`)

The `api` instance automatically attaches the Bearer token from `useAuthStore` on every request. On a `401` response (outside of `/login`), it clears auth and redirects to `/login`.

### Auth Store (`src/store/useAuthStore.ts`)

Token is persisted in a cookie (`access_token`) via `js-cookie`. The store initialises from the cookie on load. Use `setToken(token, remember?)` and `clearAuth()`.

### Component Hierarchy

- `src/components/ui/` — Shadcn-generated base components; no logic
- `src/components/common/` — Polymorphic wrappers that **replace raw HTML elements**:
  - `<Box>` → `div`, `section`, `article`, `span`, etc.
  - `<Text>` → `p`, `span`
  - `<Heading>` → `h1`–`h6`
  - `<Container>` → centered max-width wrapper
  - `<Image>` → `img`
  - `<Link>` → `a`
- `src/components/layouts/` — Global layout wrappers (`RootLayout`)

**ESLint enforces this:** using `<div>` directly is a lint error. Use `<Box>` instead.

### Forms

All forms use React Hook Form + `@hookform/resolvers/zod`. Zod schemas go in `schemas/`, TypeScript interfaces in `types/`. No inline validation logic in components. Infer form types from schemas with `z.infer<typeof schema>`.

### Styling

- Tailwind CSS v4 via `@tailwindcss/vite` plugin
- Use `cn()` from `src/lib/utils.ts` for conditional class merging (wraps `clsx` + `tailwind-merge`)
- No `any` TypeScript types
- Zelpoint-inspired dark palette: background `#0a0a0a`, surface `#171717`, accent `#0ea5e9`

### Path Alias

`@` maps to `src/` (configured in `vite.config.ts` and `tsconfig.app.json`).
